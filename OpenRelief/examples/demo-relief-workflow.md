# Demo Relief Workflow

This fictional workflow shows how OpenRelief may process one help request.

## 1. Intake

A help request arrives from the mini program. The original text and form fields are stored with source channel, timestamp, and contact visibility.

## 2. AI Structuring

AI extracts affected people count, vulnerable groups, needs, hazards, and location mentions. The output is marked as a suggestion.

## 3. Human Review

A reviewer checks whether the request is relevant, whether the location is sufficient, and whether the urgency suggestion is appropriate.

## 4. Resource Matching

The system suggests possible shelter, transport, or supply matches. A coordinator confirms whether a match is appropriate.

## 5. Task and Follow-Up

A task is created for a trusted organization or volunteer team. Communication and status updates are logged.

## 6. Briefing

Aggregated, redacted information may be used in an internal or public situation brief after editorial review.
