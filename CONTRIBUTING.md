# Contributing to OpenRelief

Thank you for considering a contribution to OpenRelief. This project welcomes contributors from humanitarian organizations, volunteer teams, research groups, product design, engineering, data science, safety, translation, and field operations.

## Contribution Principles

- Put affected people first.
- Protect privacy and dignity.
- Treat AI as decision support, not authority.
- Preserve evidence and provenance.
- Prefer small, reviewable changes.
- Use fictional or fully anonymized examples only.
- Avoid uploading personal data, contact information, medical records, private chat logs, or unverified claims about real people.

## Ways to Contribute

- Improve documentation.
- Propose humanitarian use cases.
- Add fictional example records.
- Improve AI prompt specifications.
- Add evaluation and safety cases.
- Review privacy and safety risks.
- Translate documentation.
- Report security or misuse concerns.
- Later, contribute implementation code after the repository enters the development phase.

## Before Opening an Issue

Use the most specific issue template available:

- bug report;
- feature request;
- documentation improvement;
- humanitarian use case proposal;
- safety or privacy concern.

If your issue contains sensitive information, do not post it publicly. Follow [SECURITY.md](SECURITY.md).

## Pull Request Checklist

Before submitting a pull request, confirm:

- The change is scoped and easy to review.
- No real personal data or sensitive operational data is included.
- Any AI-related change explains its safety boundary.
- Any documentation change preserves the human-in-the-loop principle.
- Relevant examples or evaluation cases are updated.
- The pull request explains how it was reviewed or tested.

## Data and Examples

All public examples must be fictional. Do not include:

- real names;
- phone numbers;
- addresses;
- ID numbers;
- precise home locations;
- private medical details;
- chat logs;
- unverified rescue claims;
- internal NGO partner records.

## AI Contributions

Prompt and evaluation contributions should include:

- purpose of the prompt;
- input assumptions;
- required output schema;
- safety constraints;
- examples of acceptable and unacceptable behavior;
- cases that require human review.

## Review Process

Maintainers review contributions for:

- humanitarian relevance;
- safety and privacy impact;
- clarity and maintainability;
- consistency with project architecture;
- evidence and attribution quality;
- risk of misuse.
